6.2.1. Überblick über die Lösungsmethoden

Lineare Gleichungssysteme (LGS) sind das Herzstück vieler technischer und mathematischer Probleme. Es gibt verschiedene Wege, diese zu lösen, abhängig davon, ob man sie mit Stift und Papier oder mit dem Computer berechnet.

6.2.1.1. Schriftlich durchführbare Methoden (analytisch)

Diese Methoden eignen sich hervorragend für kleine Systeme (z. B. \(2 \times 2\) oder \(3 \times 3\)), um das Verständnis zu schärfen. Bei größeren Systemen werden sie jedoch schnell extrem aufwendig und fehleranfällig.

HinweisDer Klassiker: Gaußsches Eliminationsverfahren

Das Gauß-Verfahren ist die universellste Methode. Ziel ist es, das Gleichungssystem durch Äquivalenzumformungen (Zeilen tauschen, addieren, multiplizieren) in eine Zeilenstufenform (Dreiecksmatrix) zu bringen. Danach kann man die Variablen durch Rückwärtseinsetzen (Rücksubstitution) einfach berechnen.

TippCramersche Regel

Die Cramersche Regel nutzt Determinanten zur Lösung. Für jede Variable wird eine Determinante berechnet, bei der eine Spalte der Koeffizientenmatrix durch den Ergebnisvektor ersetzt wird. Vorteil: Man erhält eine explizite Formel für jede Unbekannte. Nachteil: Berechnet man die Determinanten per Laplace-Entwicklung, steigt der Rechenaufwand faktoriell (\(n!\)). Für \(n > 3\) per Hand kaum machbar.

WichtigEinsetzungs- und Additionsverfahren

Diese Verfahren sind oft die ersten, die man in der Schule lernt. Man löst eine Gleichung nach einer Variablen auf und setzt sie in die anderen ein. Dies ist im Grunde eine weniger strukturierte Form des Gauß-Verfahrens und eignet sich meist nur für sehr kleine Systeme.

6.2.1.2. Computer-Algorithmen (numerisch)

Computer rechnen anders als Menschen. Sie haben Probleme mit Rundungsfehlern (Gleitkommaarithmetik) und müssen effizient mit Speicher und Rechenzeit umgehen. Daher nutzt man hier oft Zerlegungen oder iterative Verfahren.

HinweisLR-Zerlegung (LU-Decomposition)

Dies ist der Standard für dichte Matrizen in der Numerik. Die Matrix \(A\) wird in eine untere Dreiecksmatrix (\(L\) für Lower) und eine obere Dreiecksmatrix (\(U\) für Upper) zerlegt, sodass \(A = L \cdot U\). Vorteil: Hat man die Zerlegung einmal, kann man das LGS für verschiedene Ergebnisvektoren \(b\) sehr schnell lösen, ohne alles neu zu berechnen.

WarnungIterative Verfahren (Jacobi, Gauß-Seidel)

Bei riesigen Gleichungssystemen (z. B. Millionen von Gleichungen), die aber “dünn besetzt” sind (viele Nullen, z. B. bei Simulationen), sind direkte Verfahren zu speicherintensiv. Iterative Verfahren raten eine Lösung und verbessern diese schrittweise, bis der Fehler klein genug ist. Sie liefern keine exakte Lösung, aber eine hinreichend genaue Näherung.

## 6.2.2. Implementierung der Lösungsmethoden

Wir wollen nun zwei Ansätze in Python implementieren.

### 6.2.2.1. Ansatz A: Der "naive" Gauß-Algorithmus (Einfach)

Dieser Code setzt das schulische Gauß-Verfahren direkt um. Er ist gut lesbar, aber numerisch instabil (anfällig für Rundungsfehler) und nicht auf Geschwindigkeit optimiert.

```{pyodide-python}
import numpy as np

def naive_gauss_solve(A, b):
    """
    Löst Ax = b mittels naiver Gauß-Elimination.
    Achtung: Keine Pivotisierung (kann durch 0 teilen)!
    """
    n = len(b)
    # Erweitere Matrix A um Vektor b
    M = np.hstack([A, b.reshape(-1, 1)]).astype(float)
    
    # 1. Vorwärtselimination (Stufenform herstellen)
    for i in range(n):
        # Normiere die aktuelle Zeile, sodass M[i,i] = 1 wird
        factor = M[i, i]
        M[i] = M[i] / factor
        
        # Ziehe diese Zeile von allen darunterliegenden ab
        for j in range(i + 1, n):
            M[j] = M[j] - M[j, i] * M[i]
            
    # 2. Rückwärtssubstitution
    x = np.zeros(n)
    for i in range(n - 1, -1, -1):
        sum_ax = sum(M[i, j] * x[j] for j in range(i + 1, n))
        x[i] = M[i, n] - sum_ax
        
    return x

# Testsystem
A_test = np.array([[2, 1], [1, -3]])
B_test = np.array([5, -1])

print("Lösung (Naiv):", naive_gauss_solve(A_test, B_test))
```

## 6.2.1. Overview of the solution methods {#überblick-über-die-lösungsmethoden}

Systems of linear equations are at the heart of many technical and mathematical problems. There are various ways to solve them, depending on whether you compute with pen and paper or with a computer.

### 6.2.1.1. Methods for pen and paper (analytical)

These methods are excellent for small systems (e.g. $2 \times 2$ or $3 \times 3$) to sharpen your understanding. For larger systems, however, they quickly become extremely laborious and error-prone.

::: {.callout-note title="The classic: Gaussian elimination"}
**Gaussian elimination** is the most universal method.
The goal is to bring the system into **row echelon form** (triangular matrix) through equivalence transformations (swapping, adding, multiplying rows). After that, the variables can be computed easily by back substitution.
:::

::: {.callout-tip title="Cramer's rule"}
**Cramer's rule** uses determinants to solve the system.
For each variable a determinant is computed in which one column of the coefficient matrix is replaced by the right-hand side vector.
*Advantage:* You get an explicit formula for each unknown.
*Disadvantage:* If the determinants are computed by Laplace expansion, the effort grows factorially ($n!$). For $n > 3$ hardly feasible by hand.
:::

::: {.callout-important title="Substitution and elimination (addition) method"}
These methods are often the first ones you learn at school. You solve one equation for one variable and substitute it into the others. This is basically a less structured form of Gaussian elimination and is usually only suitable for very small systems.
:::

### 6.2.1.2. Computer algorithms (numerical)

Computers compute differently from humans. They have problems with rounding errors (floating-point arithmetic) and have to handle memory and computing time efficiently. That is why decompositions or iterative methods are often used here.

::: {.callout-note title="LU decomposition"}
This is the standard for dense matrices in numerical analysis.
The matrix $A$ is decomposed into a lower triangular matrix ($L$ for lower) and an upper triangular matrix ($U$ for upper), so that $A = L \cdot U$.
*Advantage:* Once you have the decomposition, you can solve the system very quickly for different right-hand sides $b$ without recomputing everything.
:::

::: {.callout-warning title="Iterative methods (Jacobi, Gauss-Seidel)"}
For huge systems (e.g. millions of equations) that are "sparse" (many zeros, e.g. in simulations), direct methods need too much memory.
Iterative methods guess a solution and improve it step by step until the error is small enough. They do not give an exact solution, but a sufficiently accurate approximation.
:::

## 6.2.2. Implementing the solution methods {#implementierung-der-lösungsmethoden}

We now want to implement two approaches in Python.

### 6.2.2.1. Approach A: the "naive" Gauss algorithm (simple)

This code implements the school version of Gaussian elimination directly. It is easy to read, but numerically unstable (prone to rounding errors) and not optimized for speed.

```{pyodide-python}
import numpy as np

def naive_gauss_solve(A, b):
    """
    Solves Ax = b using naive Gaussian elimination.
    Caution: no pivoting (may divide by 0)!
    """
    n = len(b)
    # Extend matrix A by vector b
    M = np.hstack([A, b.reshape(-1, 1)]).astype(float)

    # 1. Forward elimination (create row echelon form)
    for i in range(n):
        # Normalize the current row so that M[i,i] = 1
        factor = M[i, i]
        M[i] = M[i] / factor

        # Subtract this row from all rows below
        for j in range(i + 1, n):
            M[j] = M[j] - M[j, i] * M[i]

    # 2. Back substitution
    x = np.zeros(n)
    for i in range(n - 1, -1, -1):
        sum_ax = sum(M[i, j] * x[j] for j in range(i + 1, n))
        x[i] = M[i, n] - sum_ax

    return x

# Test system
A_test = np.array([[2, 1], [1, -3]])
B_test = np.array([5, -1])

print("Solution (naive):", naive_gauss_solve(A_test, B_test))
```

### 6.2.2.2. Approach B: the robust `numpy` solution (practice)

In practice: **don't reinvent the wheel!**
Libraries like `NumPy` already come with highly optimized and numerically stable algorithms. These are often based on robust methods such as LU decomposition (as with `numpy.linalg.solve`) and are very efficient and fast. The function `numpy.linalg.solve` is therefore the absolute standard way.

*   **Stable:** Internally uses tricks like *pivoting* to avoid division by (almost) zero. This makes the algorithm robust.
*   **Fast:** Relies on highly optimized, compiled math libraries (BLAS/LAPACK). It hardly gets faster than that.
*   **Simple:** Using it is super simple, as you will see in a moment.

```{pyodide-python}
# We use the same test system as above
C_test = np.array([[2, 1], [1, -3]])
D_test = np.array([5, -1])

# The professional and stable solution with NumPy
x_numpy = np.linalg.solve(C_test, D_test)
print("Solution (NumPy):", x_numpy)
```

### 6.2.2.3. Why pivoting matters

The naive Gauss algorithm divides each row by its diagonal element. If there is a $0$ there, it fails, even though the system has a perfectly normal solution. An example:

$$\begin{align*}
0x + 1y &= 2 \\
1x + 1y &= 3
\end{align*}$$

By hand you would simply swap the two rows. That is exactly what *pivoting* is. First run the cell of approach A so that `naive_gauss_solve` is known, then compare:

```{pyodide-python}
A_pivot = np.array([[0, 1], [1, 1]])
b_pivot = np.array([2, 3])

try:
    with np.errstate(divide="ignore", invalid="ignore"):
        print("Naive Gauss:", naive_gauss_solve(A_pivot, b_pivot))
except NameError:
    print("First run the cell of approach A.")

print("NumPy:      ", np.linalg.solve(A_pivot, b_pivot))
```

`nan` stands for *not a number*: the naive algorithm divided by $0$. `np.linalg.solve` swaps the rows internally and finds $x = 1$, $y = 2$.
